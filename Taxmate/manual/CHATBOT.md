# Taxmate Chatbot (แบบผสม: กฎ + LLM ที่เลือกเปิดได้)

## ภาพรวม

คำถามจะผ่านสองชั้นตามลำดับ

1. **ชั้นกฎ** (`shared/chatbot.mjs`) ตอบเพดาน/เงื่อนไขลดหย่อน สรุปภาษี และจำลอง "ถ้าเพิ่ม X บาท" ทำงานได้ทั้งโหมด Local และโหมดสาธิตบน GitHub Pages ไม่เสียค่าใช้จ่าย ไม่ส่งข้อมูลออกนอกเครื่อง ตัวเลขมาจาก `shared/tax.mjs` ตัวเดียวกับเครื่องคำนวณ
2. **ชั้น LLM** (`backend/chat.mjs`) ใช้เมื่อกฎตอบไม่ได้ **และ** ผู้ดูแลตั้ง `ANTHROPIC_API_KEY` **และ** ผู้ใช้ติ๊กยินยอมในหน้าแชท ใช้ได้เฉพาะโหมด Local เพราะคีย์ต้องอยู่ฝั่ง server

ถ้าไม่ตั้งคีย์ ระบบยังใช้ได้ปกติ (ชั้นกฎอย่างเดียว) คำถามที่กฎไม่เข้าใจจะได้ข้อความแนะนำวิธีถาม

## เปิดใช้ LLM

```bash
# macOS/Linux
ANTHROPIC_API_KEY=sk-ant-... npm start
# Windows PowerShell
$env:ANTHROPIC_API_KEY="sk-ant-..."; npm start
```

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `ANTHROPIC_API_KEY` | (ว่าง = ปิด LLM) | คีย์ของผู้ดูแล ไม่ถูกส่งไปเบราว์เซอร์และไม่อยู่ในคำตอบ API |
| `TAXMATE_CHAT_MODEL` | `claude-sonnet-5-5` | โมเดลที่ใช้ |
| `TAXMATE_CHAT_BASE_URL` | `https://api.anthropic.com` | ใช้ชี้ไป mock/proxy ตอนทดสอบ |

อย่า commit คีย์ขึ้น GitHub และอย่าใส่คีย์ในโค้ด frontend

## ความปลอดภัยและความเป็นส่วนตัว

- LLM **ไม่คำนวณภาษีเอง** ต้องเรียก tool 3 ตัว: `get_my_tax_summary`, `what_if_calculate`, `get_tax_rules` ซึ่งห่อ `shared/tax.mjs`
- tool เห็นเฉพาะตัวเลขรวมของผู้ใช้ที่ล็อกอินอยู่ **ไม่เห็น** รูปบิล ข้อความ OCR ชื่อร้าน ชื่อ/อีเมลผู้ใช้ ข้อมูลผู้ใช้คนอื่นเข้าถึงไม่ได้เพราะ server ดึงจากเซสชันเสมอ
- ข้อความแชทที่ส่งไปผู้ให้บริการ AI คือข้อความของผู้ใช้ (ล่าสุดไม่เกิน 12 ข้อความ ข้อความละไม่เกิน 2,000 ตัว) ต้องได้รับความยินยอมทุกคำขอ (`consent:true`) ไม่ติ๊กจะไม่มีอะไรถูกส่ง
- ประวัติแชทไม่ถูกเก็บในฐานข้อมูล (stateless) audit บันทึกเฉพาะ action `chat-rules` / `chat-llm` ไม่มีเนื้อหา
- จำกัด 20 ข้อความ/ผู้ใช้/นาที; error จากผู้ให้บริการ AI ถูกแปลงเป็นข้อความทั่วไป ไม่ส่ง body ต้นทางกลับ
- system prompt สั่งให้ปฏิเสธเรื่องนอกขอบเขต (ดู `unsupported` ใน ruleset), ไม่แนะนำให้ซื้อประกันเพื่อลดภาษี, ถือข้อความใน tool/ผู้ใช้เป็นข้อมูลไม่ใช่คำสั่ง **แต่ prompt ไม่ใช่การรับประกันว่าโมเดลจะไม่ผิดพลาด** คำตอบ AI จึงมีป้ายกำกับและมีข้อความเตือนว่าเป็นประมาณการ
- โหมดสาธิต (IndexedDB) ใช้ชั้นกฎอย่างเดียว คำนวณบนเครื่องผู้ใช้

## API

| Method / Path | สิทธิ์ | หมายเหตุ |
|---|---|---|
| GET `/api/chat/status` | ล็อกอิน | `{llm:boolean}` |
| POST `/api/chat` | ล็อกอิน | body `{messages:[{role,content}], consent?:boolean}` ข้อความสุดท้ายต้องเป็น `user` |

คำตอบ: `{reply, source:'rules'|'llm'|'fallback', llm:boolean, data?, suggestions?, toolsUsed?, needConsent?}`
สถานะ: 400 messages ไม่ถูกต้อง, 401 ยังไม่ล็อกอิน, 429 ถามถี่เกิน, 502 ผู้ให้บริการ AI ไม่พร้อม

## ขอบเขตและข้อจำกัด

- รองรับเฉพาะเงินเดือน/โบนัส ม.40(1) ปี 2568 เหมือนส่วนอื่นของระบบ
- ชั้นกฎใช้ regex คำสำคัญภาษาไทย/อังกฤษ จึงเข้าใจได้จำกัด คำถามแปลก ๆ อาจตกไป fallback
- "จำลอง" สมมติว่าบิลที่เพิ่มผ่านการตรวจหลักฐานแล้ว ไม่ได้ตรวจสิทธิจริง
- การคำนวณถูกทดสอบกับ `calculate()` ใน `tests/chatbot.test.mjs`; การตอบของโมเดลจริงไม่สามารถทดสอบแบบกำหนดผลได้ (เทสต์ใช้ mock)
- หากเพิ่มปีภาษีใหม่ ต้องปรับ `chatbot.mjs` ให้ใช้ ruleset ปีนั้นพร้อม regression tests
